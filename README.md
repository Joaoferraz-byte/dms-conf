# Noctalia configuration for Livara

This repository is the reproducible first-layer integration for **Noctalia v5** in the Livara NixOS environment. It replaces the former DMS patch layer. The repository contains a curated Noctalia TOML, a small set of reviewed v5 plugins, and the Home Manager module that installs them as store-backed files.

## Ownership model

| Layer | Owner | Contract |
|---|---|---|
| NixOS hardware, drivers, graphics, PipeWire, portals and keyd | `nix-conf` | System modules and host conditionals |
| Niri compositor, outputs, window rules and native compositor actions | `nix-conf` | Declarative KDL generated by Home Manager |
| Noctalia bar, panels, launcher, notifications, wallpaper, lockscreen, widgets and palette | This repository | `programs.noctalia` and `config/noctalia/config.toml` |
| Noctalia plugin source | This repository plus pinned upstream input | `plugins/*/plugin.toml` and immutable source links |
| Application-specific adapters | `shell-conf`/`nix-conf` | Native application contracts consuming the Noctalia palette |

The Home Manager module enables Noctalia but deliberately disables its systemd unit. Niri starts exactly one shell with `spawn-at-startup "noctalia"`, so the Wayland and D-Bus environment comes from the compositor session and there is no duplicate process.

## Declarative configuration and mutable state

`config/noctalia/config.toml` contains stable intent only. Noctalia may still write runtime settings and plugin data under the user state directory, but generated widget geometry, monitor-specific IDs, caches, last-wallpaper values and materialized plugin catalogs are not part of this repository. A clean installation receives the same source configuration and deterministic plugin sources; runtime state is recreated by Noctalia.

The built-in Niri template is intentionally not enabled because the upstream template appends an `include "noctalia.kdl"` line to the mutable `config.kdl`. Niri remains declarative in `nix-conf`. Built-in GTK, Qt, Kitty, WezTerm, Starship and KDE templates are enabled because their outputs are separate application theme contracts. The local palette template writes the dark palette consumed by legacy application adapters, while the local NixVim template writes the Lua table expected by `vim-conf`.

Community templates are disabled. They are fetched and cached at runtime rather than pinned by this flake; applications requiring a community template must be ported into `config/noctalia/templates/` with a reviewed upstream revision first.

## Plugins

The official v5 `screen_recorder` and `timer` plugins are sourced from the pinned `official-plugins` flake input. The reviewed `dotnetrob/cat` v5 plugin is stored in this repository because it is part of the selected Noctara visual configuration. Plugin API v5 is still beta, so automatic updates are disabled and the lockfile is the review boundary.

The screen recorder requires the external `gpu-screen-recorder` binary, which remains a system/package concern in `nix-conf`. Noctalia plugin state is not copied from `Noctara-Dots/local/state`; only its stable widget and theme preferences were curated.

## Flake usage

```nix
inputs.noctalia-conf = {
  url = "github:Joaoferraz-byte/noctalia-conf";
  inputs.nixpkgs.follows = "nixpkgs";
};

home-manager.sharedModules = [
  inputs.noctalia-conf.homeModules.default
];
```

During the repository rename transition, the old `github:Joaoferraz-byte/dms-conf` URL may continue to resolve through GitHub's redirect. The source tree itself contains no DMS package, patch, IPC call or module.

## Validation

Run `nix flake check --no-build` in this repository and in `nix-conf`. On hardware, verify one `noctalia` process, the user session target, the generated palette files, plugin discovery, `niri msg windows`, the wallpaper IPC, screen recorder availability and `keyd monitor`. Validate drivers, PipeWire, portals and lock/suspend behavior independently because they are intentionally outside this repository.
