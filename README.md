# Livara Noctalia

This repository owns the complete customized Noctalia shell for Livara. It pins the upstream runtime, declares the shell settings, owns the wallpaper and theme policy, stores the user templates and reviewed plugins, and exports the Home Manager module consumed by the desktop composition.

Niri remains the compositor owner in `nix-conf`. `shell-conf` is the intermediary integration layer: it imports this module and provides shell-independent helpers and application adapters, but it does not define Noctalia settings, templates, plugins, or runtime assets.

## Ownership model

| Responsibility | Owner | Contract |
| --- | --- | --- |
| Upstream Noctalia runtime | This repository | `packages.<system>.default` and `overlays.default` |
| Noctalia shell settings, wallpaper, bar, panels and widgets | This repository | `config/noctalia/config.toml` |
| Noctalia user templates and palette generation | This repository | `config/noctalia/templates` |
| Reviewed Noctalia plugins | This repository | `plugins/*` |
| Compositor, window rules and native compositor actions | `nix-conf` | Niri KDL generated by Home Manager |
| Application adapters and shell-independent support | `shell-conf` | `homeModules.support` |

## Contract

| Output | Purpose |
| --- | --- |
| `packages.<system>.default` | Upstream Noctalia package exposed through the local runtime boundary. |
| `overlays.default` | Makes the local package available as `pkgs.noctalia` when an overlay is desired. |
| `homeModules.default` | Imports the upstream Home Manager module, links the customized TOML and plugins, and disables the duplicate systemd lifecycle because Niri starts the single process. |
| `homeModules.noctalia` | Compatibility alias for the default module. |

`homeModules.default` accepts the optional `desktopProfile.monitorProfile` argument so the battery widget remains host-specific without moving shell policy into the host repository. Generated palette files and application profiles remain mutable XDG state; source configuration and plugin code remain pinned in this repository. The Spicetify user template writes the `custom` color scheme to the user configuration and uses a synchronous `spicetify apply --no-restart` hook; it requires a writable runtime Spotify installation because the Nix-built package remains immutable.

## Composition

```nix
inputs.noctalia-conf = {
  url = "github:Joaoferraz-byte/noctalia-conf";
  inputs.nixpkgs.follows = "nixpkgs";
};

inputs.shell-conf.inputs.noctalia-conf.follows = "noctalia-conf";

home-manager.sharedModules = [
  inputs.shell-conf.homeModules.support
];
```

The shell support module imports `inputs.noctalia-conf.homeModules.default`. This keeps Noctalia's source of truth in one repository while allowing `shell-conf` to connect it to session helpers, application adapters and the host profile.

## Wallpaper policy

Wallpaper selection is manual. The wallpaper picker remains available, while `[wallpaper.automation].enabled = false` prevents Noctalia from changing the wallpaper at startup or on a timer. The selected wallpaper still feeds Noctalia's palette and downstream templates.

## Validation

Run `nix flake check --no-build --no-update-lock-file --all-systems` in this repository, `shell-conf` and `nix-conf`. For the materialized configuration, validate the rendered TOML with `noctalia config validate` and verify on a target host that Niri starts exactly one Noctalia process, the wallpaper remains stable until manually selected, and the generated templates update from the selected palette.
